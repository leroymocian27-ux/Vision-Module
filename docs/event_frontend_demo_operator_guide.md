# Event Frontend Demo Operator Guide

本文面向比赛/验收演示人员，说明如何解释 `/demo/` 里的事件语义链路展示。它不是开发文档，也不是生产开关说明。

## 演示前准备

1. 确认服务已启动，并打开 `/demo/`。
2. 确认实时视频区域存在，overlay/canvas 能显示检测叠加层。
3. 确认 Raw Status 和 Diagnostics 区域可以展开或查看。
4. 确认 Event Semantic Review 面板存在。
5. 如果需要展示事件证据，先确认已有真实回放事件或使用 demo seed 产生开发演示事件。
6. 如果事件链路关闭，面板应显示“事件语义链路未启用”，页面不能报错。

## 如何解释前端区域

Pipeline 状态：说明事件语义链路是否开启，以及当前 outbox 中的事件数量和处理状态。这是事件级旁路，不是实时检测主链路本身。

事件摘要：说明本次事件是谁、在哪个摄像头、哪个 track、风险等级和置信度是多少。这里用于快速定位事件。

智能复核：解释系统为什么认为该事件有风险，包含规则复核结果、推荐动作、降级原因，以及可选 VLM 的建议性解释。

Delivery 状态：说明事件是否进入投递旁路。当前 `dry_run` 表示模拟投递或受控验收，不等同于已经正式推送主系统。

关键帧时间轴：展示疑似跌倒前后 `T-3s`、`T-1s`、`T0`、`T+1s`、`T+3s`、`T+5s` 的证据帧。缺失时会显示原因。

Timeline Image：如果事件提供安全的过程图 URL，前端会显示过程图；如果没有提供，会显示未提供或仅归档状态。

## 推荐话术

- “实时检测链路先给出跌倒候选，事件链路负责把前后证据整理出来。”
- “事件链路会抽取关键帧形成证据包，方便复核和验收。”
- “规则和可选 VLM 复核用于解释风险，不阻塞实时检测。”
- “当前投递处于 dry-run 或受控验收模式时，只表示模拟投递完成。”
- “系统保留原主系统告警链路，新增事件语义旁路用于增强解释和归档。”

## 禁止话术

- 不要说“大模型直接判断跌倒”。
- 不要说“已经正式推送主系统”，除非 Delivery 明确是 `sent + post + dry_run=false` 且经过单独验收。
- 不要说“系统能医疗诊断老人受伤情况”。
- 不要把 demo seed 事件说成真实生产事件。
- 不要把 VLM fallback 说成模型已经稳定在线。

## 常见异常解释

没有事件：当前没有可展示的事件归档，面板会显示“暂无事件归档”。

没有图片：关键帧可能缺失、未归档，或安全访问接口未开启。面板会显示 `missing_reason`，不会请求本地路径。

VLM 未启用：当前展示的是规则复核结果。VLM 是可选建议链路，默认不启用。

Delivery 未启用：当前没有投递状态，说明投递旁路未开启或没有对应记录。

dry_run：表示模拟投递，不是正式报警或正式 POST。

retry/failed：表示投递旁路在等待重试或已经失败。演示时只说明状态，不展示内部 endpoint、token 或完整错误堆栈。

## 最终演示话术边界

dry-run：说“模拟投递完成”或“受控验收模式”，不要说“已经正式推送主系统”。

VLM disabled：说“当前显示规则复核结果，VLM 可选链路未启用”，不要说“模型已经在线参与判断”。

Ollama advisory-only：说“本地语义模型用于事件级辅助解释”，不要说“本地模型实时判定跌倒”。

规则复核：说“规则复核用于整理事件证据和风险解释”，不要说“规则复核替代实时检测主链路”。

关键帧：说“事件链路抽取前后关键帧形成证据包”，不要说“前端伪造了事件证据”。

正式报警链路：说“原正式主系统告警链路仍保留”，不要说“Event Semantic Review 面板已经替换主系统报警”。
