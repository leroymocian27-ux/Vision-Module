# 低延迟三关键帧配置

当前实时链路使用如下配置：

```text
POST_FALL_V2_SAMPLE_FPS=3
POST_FALL_V2_MIN_POSITIVE_FRAMES=4
POST_FALL_V2_MIN_CONSECUTIVE_FRAMES=3
POST_FALL_V2_CANDIDATE_MIN_MS=800
EVENT_KEYFRAME_OFFSETS_MS=-1000,0,3000
POST_FALL_V2_QWEN_MAX_IMAGES=3
POST_FALL_V2_KEYFRAME_COLLECTION_TIMEOUT_SECONDS=3.5
```

## 三张图片的职责

| 偏移量 | 角色 | 千问检查重点 |
| --- | --- | --- |
| `-1000 ms` | `pre_fall` | 人员跌倒前的姿态，或开始失衡的迹象。 |
| `0 ms` | `trigger` | 二分类确认候选时的动作和姿态。 |
| `+3000 ms` | `post_fall` | 倒地后的持续状态、是否自主恢复，以及人与地面的关系。 |

三张图片不是任意抽取：它们保留了时间顺序，使千问仍可区分“失衡后倒地”和“从一开始就稳定躺卧或受控躺下”。书本、手机、垫子只作场景辅助信息，不单独决定结论。

## 时延影响

采样从 `5 FPS` 降为 `3 FPS` 后，二分类仍保持 `4` 个阳性帧、`3` 个连续阳性帧和 `800 ms` 的防抖门槛。因此二分类事件通常在首个持续阳性画面后约 `1 秒`建立，较原先可能增加约 `0.2 秒`，换取相同级别的连续证据。

千问不再等待 `+5000 ms` 关键帧，最大关键帧等待由约 `5 秒`降至约 `3 秒`；同时输入图片从 `6` 张降至 `3` 张，JPEG 编码、传输和视觉推理负载也会下降。最终 JSON 的正常总时延预期比原配置减少约 `2 秒`以上，实际千问推理缩短幅度取决于 GPU 和本机 Ollama 负载。

历史事件目录不修改；只有服务重启后的新事件采用三关键帧配置。
